# CLAUDE.md

Guidance for Claude Code (and humans) working on this repository.

## What this project is

`ngs-preflight` checks the inputs of a sequencing analysis before it runs: a target BED file, a
sample sheet, a reference, and optionally sample identity (via somalier). Its purpose is to turn
problems that would otherwise appear hours into a run (or never) into short, plain-language
messages that say what is wrong and how to fix it. It is a general-purpose tool; keep it that way.

In scope: file-format and consistency checks, reports for people and for pipelines.
Out of scope: variant calling, alignment, clinical interpretation, anything that needs a network.

## Layout

- `src/ngs_preflight/checks/`: one module per check group. Each check is a function decorated
  with `@check(...)` in `registry.py`; the decorator holds the ID, severity, title, message
  template, technical detail and suggested fix. `docs/checks.md` is generated from it.
- `src/ngs_preflight/report/`: text, JSON, Markdown and HTML renderers over one pydantic `Report`.
- `src/ngs_preflight/identity/`: the somalier wrapper. Everything else is pure Python.
- `tests/data/`: hand-made fixtures, one per failure mode, each with an `*.expected.json`.

## Conventions

- Typed Python 3.11+, `mypy --strict` clean, `ruff` for lint and format (line length 100).
- Runtime dependencies stay minimal: pydantic v2, rich, jinja2, pyyaml. No compiled dependencies.
- Messages are for lab staff, not programmers: short sentences, say what it means, say what to do.
  Message and fix text are templates filled from `Hit.params`; check the grammar for 1 and many.
- Every check has at least one positive and one negative fixture.
- Every number that appears in the docs is generated, never typed. `docs/checks.md`,
  `docs/report.schema.json` and `examples/reports/*` are produced by `preflight docs` and
  `python scripts/build_examples.py`; tests fail if they are stale.
- Never edit user files in place. Anything that writes a corrected file writes a new one.
- The 1-based-coordinate check (BED007) is a heuristic. Its message must say so, and it must stay
  silent on the "good" example.
- Real tool output is the source of truth for somalier fixtures: do not hand-edit `.somalier` files. `tests/data/identity/observed.json` and `docs/identity-fixtures.md` are regenerated by `scripts/record_identity_observations.py` (needs somalier).

## Running things

```bash
python -m pip install -e ".[dev]"
python -m pytest                      # everything except tests that need somalier runs by default
python -m pytest -m somalier          # real somalier (PREFLIGHT_SOMALIER_CMD or a binary on PATH)
python -m ruff check . && python -m ruff format --check .
python -m mypy --strict src
python -m ngs_preflight docs          # regenerate docs/checks.md and docs/report.schema.json
python scripts/build_examples.py      # regenerate examples/ and examples/reports/
```

CI runs the same commands on Python 3.11, 3.12 and 3.13 (and Windows), requires 90% line coverage
on `checks/`, and runs the somalier tests in the `brentp/somalier` container.

## Review rule

Changes written by Claude are reviewed and the tests are run before they are committed. Use
conventional commit messages (`feat:`, `fix:`, `docs:`, `test:`, `chore:`). Work on a branch and
open a pull request, even when working alone, so the CI history stays visible.
